class Neo4jQuery:
    def __init__(self, llm: LLMAccessLayer, neo4j_connection: Neo4jConnection):
        self.llm = llm
        self.neo4j_connection = neo4j_connection

    def _query_database(self, neo4j_query, params={}):
        result = self.neo4j_connection.query(neo4j_query, params)
        output = [r.values() for r in result]
        output.insert(0, result.keys())
        return output

    def _construct_cypher(self, question, history=None):
        messages = [
            {"role": "system", "content": get_system_message(get_java_message())},
            {"role": "user", "content": question},
        ]
        # Used for Cypher healing flows
        if history:
            messages.extend(history)

        completions = self.llm.chat_completion(
            model="qwen3:14b",#deepseek-r1:14b",
            temperature=0.0,
            messages=messages
        )
        return completions

    def run(self, question):
        return self._run(question, None, True)

        except CypherSyntaxError as e:

            if not retry:

Great question! Hybrid search combines the strengths of both semantic (vector) search and traditional keyword search. Here are the main approaches:

## 1. **Parallel Search + Score Fusion**

**How it works**:
- Run semantic search and keyword search in parallel
- Combine results using score fusion techniques
- Rank final results by combined scores

**Score Fusion Methods**:
- **Linear combination**: `final_score = α * semantic_score + β * keyword_score`
- **Reciprocal Rank Fusion (RRF)**: `score = Σ(1/(rank + k))` for each search type
- **Weighted fusion**: Adjust weights based on query characteristics

**Implementation approach**:
```python
# Pseudocode structure
semantic_results = vector_db.similarity_search(embedded_query, top_k=50)
keyword_results = search_engine.search(query_text, top_k=50)

# Normalize scores to [0,1] range
normalized_semantic = normalize_scores(semantic_results)
normalized_keyword = normalize_scores(keyword_results)

# Combine and re-rank
final_results = fuse_results(normalized_semantic, normalized_keyword)
```

## 2. **Dense-Sparse Vector Combination**

**How it works**:
- Use models that produce both dense (semantic) and sparse (keyword) embeddings
- Combine at the vector level before search

**Popular approaches**:
- **SPLADE**: Learns sparse representations alongside dense ones
- **ColBERT**: Multi-vector approach with term-level matching
- **BGE-M3**: Unified model for dense, sparse, and multi-vector retrieval

## 3. **Query Analysis + Adaptive Weighting**

**How it works**:
- Analyze the query to determine optimal search strategy
- Adjust weights dynamically based on query characteristics

**Query characteristics to consider**:
- **Exact terminology**: Higher keyword weight for technical terms, API names
- **Conceptual questions**: Higher semantic weight for "how does X work?"
- **Code pattern queries**: Balanced approach for "find examples of Y"
- **Query length**: Short queries favor keyword, longer favor semantic

**Dynamic weighting examples**:
```python
# Pseudocode
if contains_code_identifiers(query):
    keyword_weight = 0.7
    semantic_weight = 0.3
elif is_conceptual_question(query):
    keyword_weight = 0.3
    semantic_weight = 0.7
else:
    keyword_weight = 0.5
    semantic_weight = 0.5
```

## 4. **Multi-Stage Retrieval**

**How it works**:
- Use keyword search as initial filter (fast, broad recall)
- Apply semantic search for re-ranking (precise, contextual)

**Benefits**:
- Computationally efficient
- Ensures important keyword matches aren't missed
- Semantic layer improves relevance ranking

## 5. **Field-Specific Hybrid Search**

**How it works**:
- Apply different search strategies to different documentation fields
- Combine results from multiple fields

**Field strategies**:
- **Class/method names**: Exact match + fuzzy keyword search
- **Documentation**: Semantic search for concepts
- **Code snippets**: Token-based keyword search
- **Comments**: Hybrid semantic + keyword

## Implementation Considerations

**Score Normalization**:
- Min-max scaling: `(score - min) / (max - min)`
- Z-score normalization: `(score - mean) / std`
- Sigmoid normalization for unbounded scores

**Performance Optimization**:
- Index both vector and keyword data efficiently
- Use approximate nearest neighbor (ANN) for vector search
- Implement result caching for common queries
- Consider parallel processing for large datasets

**Quality Metrics**:
- Track precision@k and recall@k for both methods
- Monitor click-through rates and user feedback
- A/B test different fusion strategies

## Recommended Starting Approach

1. **Begin with simple linear fusion** (easiest to implement and tune)
2. **Use fixed weights initially** (e.g., 60% semantic, 40% keyword)
3. **Implement query analysis** to adjust weights based on query type
4. **Add result diversification** to avoid redundant results
5. **Iterate based on user feedback** and performance metrics

The key is to start simple and gradually add sophistication based on your specific use cases and user feedback patterns!
